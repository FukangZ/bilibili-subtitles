## 写作与维护约定

- 一篇围绕一个决策，写清当时的背景、选择、理由与接受的代价，让读者不打开其他文档也能理解这项取舍。篇幅和小标题按实际需要安排，备选方案只记录有依据的比较。
- 决策正文不引用项目或包 README，也不以“具体规则见当前文档”代替关键背景。可以引用相关 ADR 或补充证据；证据的版本会影响结论时，注明版本或链接具体 commit。
- 日期、版本和代码链接按追溯需要补充，不作为每篇固定必填项；补充信息应有可核实的依据。
- 已采纳记录保留原有决定与论证。关键决定或边界变化时，新建 ADR 说明变化原因并链接旧记录，旧记录更新状态并链接新记录。新编号从现有最大值递增，既有编号保持不变。
- 状态使用 `proposed`（待决定）、`accepted`（已采纳且未被取代）、`deprecated`（已废弃）或 `superseded by ADR-NNNN`（被指定记录取代）。
- 错字、排版和不改变含义的修订可原位编辑；影响原始论证的事实纠错、后续发现或补充分析，以带日期的说明追加，区分当时的判断与后来的认识。
