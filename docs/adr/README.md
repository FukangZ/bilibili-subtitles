# 当前架构决策

这些 ADR（Architecture Decision Record，架构决策记录）解释**当前架构为什么这样设计，以及接受了什么代价**，不是开发过程的历史日志。它们根据当前代码和产品目标整理，不声称还原当时的讨论、备选方案或决策日期。

先看 [架构总览](../architecture.md) 了解系统如何组成，再按以下顺序阅读理由。编号按本轮整理后的叙述顺序排列，不表示实施时间。

## 写作与维护约定

- 一篇围绕一个需要解释的选择；写清问题、当前决定和代价即可。复杂取舍再展开，不要求凑齐模板小标题。
- 可替代方案是对当前设计的比较，不自动代表曾经实现或讨论过。`accepted` 只表示当前采用，不表示质量或安全已获证明。
- API、配置表、字段、权限与操作步骤分别维护在包 README、[安全政策](../../SECURITY.md)、[贡献指南](../../CONTRIBUTING.md) 和 [发布指南](../publishing.md)。ADR 不复制完整规范、逐函数说明或测试清单。
- 补充理由、修正事实和链接可原位编辑；改变关键边界时同步说明新取舍，并消除相互冲突的当前说明。新增记录从下一个编号继续，不为插入阅读顺序而重复重排。
- 每篇只链接少量关键依据。模拟测试只能验证程序约束，不能证明真实平台长期可用、模型忠实或供应商没有计费。
