# Pi 复用宿主模型、认证和终端交互

Pi 已提供模型注册、认证、思考能力和终端界面。插件因此只注册下载、润色工具与扫码命令，将这些能力适配到 core，而不是再维护一套模型连接和登录 UI。这样用户可以延用会话设置，代价是 Pi 特有的模型预检、终态转换和结果回填不能直接搬到其他宿主。

## 为什么显式配置与继承配置区别处理

显式指定了模型或思考强度，就意味着用户主动选择了费用、能力或数据接收方；不支持时应报错。继承的思考值则可能来自另一模型，切换模型后可以按能力降级并给出警告。这比一律静默回退更可解释，也比对所有继承差异都失败更适合会话使用。

## 为什么工具只返回路径和简短结果

正文已经写入文件，再把全文塞回主对话会重复消耗上下文。工具默认交付路径、统计和用量，Agent 需要讨论内容时再读取文件。润色请求独立于主对话历史，禁用工具选择；截断、工具调用终态和空正文不能作为成功结果交给 core。

失败结果也可能已有模型消耗，因此适配器通过宿主 `tool_result` 事件补回已知用量。Pi 要求的费用字段只在边界补齐，不把补零写回 core 的未知状态；它无法恢复供应商从未报告的部分。
