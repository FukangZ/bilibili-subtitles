# 让润色模型与主对话模型独立选择

主对话需要规划和工具调用，字幕润色则是固定的长文本任务。强制使用同一模型，会把主对话的质量偏好、响应速度和费用直接带入每次全文处理。因此 Pi 与 dsh 可以继承会话模型，也可以单独指定润色模型和思考强度；CLI 没有主对话，使用自己的连接配置。

## 当前选择

模型选择在适配层完成，core 只接收准备好的客户端和展示信息。一轮润色的结构、正文及格式修复复用同一个已选择的客户端，不在阶段间自动切换。显式指定的模型不可用时直接失败，不悄悄换一个费用、数据接收方或质量不同的模型。

请求只包含字幕任务的提示词与文本，不复制主对话历史；Pi / dsh 复用宿主认证不等于让主 Agent 用一次普通回答代替文件生成。独立上下文也减少了把不相关对话带给润色模型的必要性。

## 取舍

用户可以分别权衡质量、速度与预算，但项目不自动判断哪个模型最便宜或最好。独立配置增加了认证和能力校验，不同入口的思考选项也受宿主约束。降低思考强度不保证按比例降费，换模型更不能消除两次全文请求的长度限制。

配置规则分别见 [Pi](../../packages/pi/README.md#按需配置)、[dsh](../../packages/dsh/README.md) 和 [CLI](../../packages/cli/README.md#配置文件说明)。调用边界由各包的 `src/model.ts` 或 CLI 的 `src/client.ts` 实现；用量解释见 [0012](0012-reported-usage-and-unknown-cost.md)。
