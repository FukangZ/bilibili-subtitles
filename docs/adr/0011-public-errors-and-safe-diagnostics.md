# 统一公共错误含义，只公开安全诊断

不同入口的原始异常结构不同，但调用方应按失败含义决定下一步。例如没有中文字幕不能自动转成翻译，模型认证失败也不同于 B 站未登录。因此适配器将宿主和供应商结果映射到 core 的稳定错误码，各入口再补充适合自身的恢复提示，不要求用户匹配上游原文。

## 为什么不透传异常

上游 message、响应体、URL、headers 或堆栈可能包含密钥、提示词和字幕。公共结果因此使用固定安全消息，只投影经过校验的诊断字段，不展开 `cause` 或任意 `details`。代价是丢失部分排障细节，未知失败也可能只能归为通用模型错误；不能为了显得具体就猜测分类。

阶段和尝试由 core 提供，适配器不解析提示词或凭调用次数推断。诊断可以定位调用准备、流读取或校验失败，但不成为另一条泄露原文的通道。

## 三端并非观察到同样的信息

- dsh 依据宿主结构化 failure / code 分类，不从任意上游文本补猜。
- CLI 读取 pi-ai 的终态和上下文溢出判断，并在内部识别认证、限流文本。
- Pi 为兼容宿主错误，会在内部识别部分认证、上下文和限流文本。

后两项是现存兼容限制，不是扩展任意文本分类或公开原文的授权。统一公共错误不代表任意提供商异常都能精确恢复；内部读取与对外回显是两件事。

公共错误码以 [Core 文档](../../packages/core/README.md#错误码) 为准，诊断字段契约见其 [模型适配](../../packages/core/README.md#模型适配)，安全限制见 [SECURITY](../../SECURITY.md)。实现集中在各适配器模型模块；失败用量单独见 [0012](0012-reported-usage-and-unknown-cost.md)。
