# 统一公共错误含义，只公开安全诊断

不同入口的原始异常结构不同，但调用方应按失败含义决定下一步。因此适配器将宿主和供应商结果映射到 core 的稳定错误码，各入口再补充适合自身的恢复提示，不要求用户匹配上游原文。例如：

- `AUTH_REQUIRED` 表示 B 站凭据缺失、失效或接口未授权，需要处理 B 站登录；`MODEL_AUTH_REQUIRED` 则需要处理模型认证，两者不能共用恢复入口。
- `LANGUAGE_NOT_AVAILABLE` 表示存在字幕但没有中文轨道，不能自动改做翻译；`NO_SUBTITLE` 表示没有可用字幕或正文为空，也不能自动转成语音识别。
- `OUTPUT_TRUNCATED` 表示输出达到上限或缺少完整终态，不能将现有片段当成完整文章交付。

## 为什么不透传异常

上游 message、响应体、URL、headers 或堆栈可能包含密钥、提示词和字幕。公共结果因此使用固定安全消息，只投影经过校验的诊断字段，不展开 `cause` 或任意 `details`。代价是丢失部分排障细节，未知失败也可能只能归为通用模型错误；不能为了显得具体就猜测分类。

阶段和尝试由 core 提供，适配器不解析提示词或凭调用次数推断。通用诊断只接受以下可缺省字段：

- `stage` 为 `structure` 或 `body`，区分结构与正文阶段；`attempt` 为 `1` 或 `2`，区分首次请求与格式修复。
- `operation` 为 `prepare`、`stream` 或 `validate`，定位调用准备、流读取或结果校验。
- `reason` 为 `timeout`、`upstream` 或 `invalid_output`，描述超时、上游失败或输出不合格。

这些受限值可以帮助排障，但未知信息保持缺失，不从任意异常内容补造字段，避免诊断成为另一条泄露原文的通道。

## 三端并非观察到同样的信息

- dsh 依据宿主结构化 failure / code 分类，不从任意上游文本补猜；诊断中还可附带白名单宿主错误码 `hostCode`、100–599 的整数 `httpStatus` 和非负安全整数 `retryAfterMs`。
- CLI 读取 pi-ai 的终态和上下文溢出判断，并在内部识别认证、限流文本。
- Pi 为兼容宿主错误，会在内部识别部分认证、上下文和限流文本。

后两项是现存兼容限制，不是扩展任意文本分类或公开原文的授权。统一公共错误不代表任意提供商异常都能精确恢复；内部读取与对外回显是两件事。

失败分类与安全诊断不抹去已经发生的模型消耗；失败用量的累计另见 [0012](0012-reported-usage-and-unknown-cost.md)。
